# Make pictures, clips and 3D splats on your own machine, and see them in a space

Write a prompt, and three local models turn it into a picture, then a short clip and a Gaussian splat (a 3D object drawn as many small soft blobs of color) made from that picture. You can turn a splat and look at it from any side. The results open as their own space, where each one sits on its own node, linked to what it was made from, and one splat can become the background of the space.

### Made on one machine, with no cloud service

| Step | Tool | Model | License | What it made |
|---|---|---|---|---|
| Picture from a prompt | stable-diffusion.cpp | Z-Image-Turbo | MIT and Apache-2.0 | a 768×768 picture |
| Clip from the picture | stable-diffusion.cpp | Wan2.2 TI2V-5B | MIT and Apache-2.0 | a 3-second, 49-frame clip |
| Splat from the picture | TripoSplat | TripoSplat | MIT | 32,768 or 65,536 Gaussians |

All three run on your own computer. The command is `npm run gen:assets`, which reads made-up prompts from `scripts/content/gen-briefs.json`. Each result gets a receipt beside it that names the tool, every model file with its fingerprint (a SHA-256 hash) and license, the prompt, the seed, how long it took, and whether the result passed its check. Tools and model files live outside the project folder; `scripts/content/gen-setup.sh` downloads them.

### A result is accepted by a check, not by the tool

A model can write a grey square, a clip in which nothing moves, or a splat full of broken numbers, and still report success. So every result is checked by code that knows nothing about the model. The picture must not be flat. The clip must play, and how much it moves is measured. The splat must have the expected number of blobs, real numbers, a real size and visible blobs. On the first run the splat check found a fault in TripoSplat's own file writer: thousands of blobs were saved with an infinite opacity. The pipeline now repairs those values and records how many it repaired.

### A generated splat is invented

TripoSplat guesses the far side of an object from one picture. A splat made this way is decoration, not a record of anything real, and the space says so. A splat rebuilt from many real photographs is a different thing and is not part of this workflow.

## How these screenshots were made

**What they show.** The pictures, clips and splats are the committed results of one run of `npm run gen:assets` on one machine with an NVIDIA RTX 3090 graphics card, on 2026-10-14. Every prompt is made up for this example.

**What is not run here.** The browser test cannot run the models, because the machines that run the tests have no graphics card. For each result it checks that the file the app shows is byte for byte the one its receipt describes, that its check accepted it when it was made, and that the app shows it. Whether the models still produce good results is checked only when someone runs `npm run gen:assets` again.

## The steps

### 1. Open the Generated assets example as its own space

Under example data on the About page (or from the welcome page), choose Generated assets. It opens as a new space of its own and shows its graph, so trying it never mixes into the space you were working in. Opening it again refreshes that same space rather than making a second one.

Where: the About page (`/about`).

<figure class="workflow-shot"><img src="/workflows/generated-assets/01-open-example.webp" width="1280" height="800" alt="Screenshot of step 1, Open the Generated assets example as its own space. A pink box labelled &quot;Generated assets&quot; marks the Generated assets card under example data." loading="lazy" decoding="async" /><figcaption>The pink box marks the Generated assets card under example data.</figcaption></figure>

**What the test checks.** The card offers to open the example as a space; choosing it lands on the graph of the new space, and the Spaces tab then shows Generated assets as the current space.

### 2. See the pipeline in the graph

Each result is a node, linked to what it was made from: a prompt to its picture, and the picture to its clip and its splat. Each node also holds the facts its receipt recorded: the model, the license, the seed and how long it took. Turn on preview all to see every result on its node. A node with a splat is drawn inside its splat, which turns slowly.

Where: the graph (`/`).

<figure class="workflow-shot"><img src="/workflows/generated-assets/02-see-pipeline.webp" width="1280" height="800" alt="Screenshot of step 2, See the pipeline in the graph. A pink box labelled &quot;Prompt → picture → clip and splat&quot; marks the graph, where each prompt links to its picture and the picture links to its clip and its splat." loading="lazy" decoding="async" /><figcaption>The pink box marks the graph, where each prompt links to its picture and the picture links to its clip and its splat.</figcaption></figure>

**What the test checks.** With previews on, at least three results show on their nodes (which ones are in view depends on where the layout puts them), and the 3D graph reports both node splats loaded and none failed.

### 3. The picture, made from a prompt

Z-Image-Turbo, run by stable-diffusion.cpp, turned the prompt into a 768×768 picture in eight steps. Find the picture's node (searching for its name works when it is out of view) and choose its preview to see it large. This picture is the starting point for the next two steps.

Where: the graph (`/`).

<figure class="workflow-shot"><img src="/workflows/generated-assets/03-picture.webp" width="1280" height="800" alt="Screenshot of step 3, The picture, made from a prompt. A pink box labelled &quot;Made by Z-Image-Turbo&quot; marks the enlarged picture." loading="lazy" decoding="async" /><figcaption>The pink box marks the enlarged picture.</figcaption></figure>

**What the test checks.** The picture the app shows is byte for byte the file its receipt describes (same SHA-256), its check accepted it, its models are MIT or Apache-2.0 licensed, and it opens large at 768 pixels wide.

### 4. The clip, made from the picture

Wan2.2 TI2V-5B, also run by stable-diffusion.cpp, started from the picture and a second prompt describing the motion, and made a 49-frame clip. The check measures how much the last frame differs from the first, because a video model can return a clip in which almost nothing moves. When that happens the receipt says so rather than calling the clip fine.

Where: the graph (`/`).

<figure class="workflow-shot"><img src="/workflows/generated-assets/04-video.webp" width="1280" height="800" alt="Screenshot of step 4, The clip, made from the picture. A pink box labelled &quot;Made by Wan2.2&quot; marks the clip, paused part way through." loading="lazy" decoding="async" /><figcaption>The pink box marks the clip, paused part way through.</figcaption></figure>

**What the test checks.** The clip the app shows matches its receipt, its check accepted it, and it loads in the viewer at 512 pixels wide. The screenshot shows a frame from the middle of the clip.

### 5. The splat, made from the picture

TripoSplat turned the same picture into 32,768 Gaussians, writing a PLY file of about 2 MB. The first prompt asked for a flat carving seen from above, and TripoSplat made it as flat as a coin; asking for a three-quarter view with a domed shell gave it real depth. Choose the splat on its node to turn it and look at it from any side. Everything it shows on the far side of the turtle was guessed from one picture.

Where: the graph (`/`).

<figure class="workflow-shot"><img src="/workflows/generated-assets/05-splat.webp" width="1280" height="800" alt="Screenshot of step 5, The splat, made from the picture. A pink box labelled &quot;Made by TripoSplat&quot; marks the splat viewer, which turns the splat slowly and can be dragged." loading="lazy" decoding="async" /><figcaption>The pink box marks the splat viewer, which turns the splat slowly and can be dragged.</figcaption></figure>

**What the test checks.** The splat the app shows matches its receipt and its check accepted it, and the viewer reports that it has loaded. The renderer is Gaussian-Splat-Lite, which the app loads only when a splat is on screen.

### 6. Set a splat as the background of the space

Open the lighthouse island splat and choose Set as background. The island is then drawn large behind the graph, sized to the graph and turning very slowly, and it never gets in the way of choosing a node. The choice is saved with the space, so it travels with an export. Clear background removes it.

Where: the graph (`/`).

<figure class="workflow-shot"><img src="/workflows/generated-assets/06-background.webp" width="1280" height="800" alt="Screenshot of step 6, Set a splat as the background of the space. A pink box labelled &quot;The island behind the graph&quot; marks the graph with the lighthouse island splat drawn behind it." loading="lazy" decoding="async" /><figcaption>The pink box marks the graph with the lighthouse island splat drawn behind it.</figcaption></figure>

**What the test checks.** The island splat matches its receipt. After Set as background the same control offers Clear background, which shows the setting was saved to the space, and the 3D graph reports three splats loaded and none failed: the two on their nodes and the island. Where the island sits and how it looks is shown by the screenshot, not measured by the test.

This workflow is run by `tests/e2e/workflow-generated-assets.test.ts`, which reads the steps above from the same list.

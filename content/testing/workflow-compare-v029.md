# Read a note against what you hold, see it on the canvas, decide a contradiction

Adding a second note to a knowledge base that already holds a project is where it goes wrong quietly: the new note repeats some of what you have, words some of it differently, contradicts some, and adds some that is new. Here a check-in note is read against the Quick-Start example and lands in Review's compare flow, where each statement is labeled by what it would do. The same comparison is drawn over your own canvas, and the one contradiction, a moved deadline, is decided on its own card, with the replaced statement kept on record.

The steps are a story inside the Quick-Start example itself, which the walk starts with open. A browser test plays that story on every change.

## How these screenshots were made

**What they show.** The Quick-Start example, opened as its own space, and one invented check-in note about its project (`tests/fixtures/compare-demo/notes.json`, the entry named quickstart). The note repeats the project's status, moves its deadline, adds a trial to a method the example names a little differently, and adds a person's task.

**What is scripted.** The test uses no language model: a stand-in reader returns the statements written down for the note. The near-duplicate label uses a test stand-in for the embedding model, so the picture proves the wiring and not how well the real model judges similar names.

**What is not shown.** How well a real model reads the note, and comparing one whole knowledge base against another, which is no longer part of Review.

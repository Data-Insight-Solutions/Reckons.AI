# How this site is built

This site is not written. It is **composed** — from the same knowledge graph that describes
Reckons.AI to itself. This page explains how, and is honest about what does not work yet.

It is also the one page here that is genuinely hand-written. That is deliberate, and the reason
is explained at the bottom.

## The problem this solves

Until recently `/docs` published **one page per entity**. Any subject in the documentation graphs
carrying a type became its own file, which produced **269 pages** sorted alphabetically with no
editorial layer. The sidebar was 23,000 pixels tall and held 815 links. Real documentation sat
beside internal bookkeeping like *"GUIDE.md → Superseded"* — a note about this repository's own
file migration, published as public documentation.

Nothing had gone wrong mechanically. The generator did exactly what it was told. The mistake was
in what it was told: **"has a type" was standing in for "is a page someone would want to read"**,
so the graph was deciding the site's information architecture by accident.

## Three graphs, not one

The site is described by three graphs with different jobs.

**The design graph** (`static/website.ttl`) says what the site *should* be. Eight pages, each
declaring which datasets it draws on and — required, not optional — **why a reader would open
it**. A page with no stated purpose is refused at build time, because a page nobody can state the
point of is precisely what the 269 already were.

It uses standard vocabulary rather than invented terms: `schema:WebPage` for pages,
`schema:isBasedOn` for the source relation, `schema:abstract` for purpose, `void:Dataset` for each
source graph, and `dcat:Catalog` to hold the set together.

**The status graph** (`static/website-status.ttl`) says what the site *actually is*. It is
generated by walking the published files and reading each one through the same parser the site
uses. Crucially it is derived **from the output**, never written alongside it — a status graph
produced from the same source as the pages would agree with itself by construction and prove
nothing.

**The archive** is git, for now. That is a deliberate choice rather than a gap: for text under
version control, a parallel journal would duplicate what git already does well.

## Composition

Each page declares its sources, and composition gathers the matching entities into it, grouped by
which graph each part came from. One page can draw on several graphs — *How it works* composes
both the architecture and the triples-and-RDF datasets, and says which section came from which.

The safeguard matters more than the feature: **composition refuses to run if any entity would be
left unclaimed.** Reducing 269 pages to 8 is an editorial act, and the difference between
*curated* and *we lost 250 pages of content* is entirely whether the leftovers are visible. Run
`npm run docs:consolidate` and it reports exactly what every page covers and what nothing covers.

Some entities are **deliberately excluded**, and an exclusion is not the same as an oversight. The
markdown-migration tracker — those 22 *"→ Superseded"* entries — is excluded by a rule that
carries its reason. An exclusion without a stated reason is refused.

## Cross-links are derived, not written

Entities relate to each other in the graph. When consolidation moved them onto shared pages those
relationships did not disappear — they became invisible. So the generator reads them back and
emits a **See also** line pointing at whichever page now holds the related entity. Nobody
maintains those links. They are recomputed on every build, and they cannot rot into pointing at a
page that no longer exists.

## The site measures itself

```
npm run website:align
```

This compares the design graph against the observed status graph and scores the gap. It keeps four
kinds of divergence separate, because they need different responses:

- **Undeclared** — published, but the design never asked for it. Wants a decision.
- **Unbuilt** — designed, but does not exist. Wants building.
- **Divergent** — exists in both, and they disagree. The only unambiguous bug.
- **Aligned** — agreement.

When this consolidation began the score was **0%**: 271 pages the design did not describe and 8
designed pages that did not exist. *"The docs are a mess"* is true and unactionable; **0% aligned,
271 undeclared** is the same statement in a form you can work to zero.

## What is not built

Stating this plainly is a house rule here — a plan written in the present tense is a lie with good
manners.

- **The status graph observes files, not rendering.** It knows a page exists and what it claims to
  be. It cannot tell you what a browser actually painted, so a page can appear correct and render
  broken. The graph records those blind spots explicitly rather than leaving them implied.
- **Section variety.** Every composed section renders the same way — a heading and a definition.
  Cards, callouts and richer layouts are not expressible in the design graph yet.
- **Links into the graph view.** A page cannot yet link a reader to the interactive graph its
  content came from. The deep link does not exist: the app's `?kb=` parameter names a local
  database, not one of these published graphs.
- **Design intent is only partly checked.** The graph declares things like disclosure style, and
  nothing yet verifies the rendered page honours them.

## Why this page is hand-written

Every other page here is generated, and editing one directly would be pointless — the next build
overwrites it.

This page carries no source declaration, which is what marks it hand-authored. The generator skips
it entirely, the alignment report still counts it, and it is safe to edit by hand or through the
CMS. That distinction is the seam the site is being refined through: **generated pages are changed
by editing the graph; pages like this one are changed by writing.**

The harder question is what happens when someone edits a generated page to add their own voice.
Today the answer is that the next regeneration overwrites it. That is a known limitation with a
plan behind it, not a decision anyone is happy with.
